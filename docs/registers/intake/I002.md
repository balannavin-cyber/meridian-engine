## 2. Row 18 decision: one negation block in the root `.gitignore`, the root rule stays

Decided by the engine lane 2026-11-23; the operator can overrule.

- **Keep** the repo-wide `*.log`, `*.csv`, `*.txt` rule. The production tree writes logs and data files at many paths; narrowing the rule would surface them as untracked on the box and put them one `git add .` from a commit.
- **Add** to the root file, after those rules: `!docs/research/**/*.txt`, `!docs/research/**/*.csv`, `!docs/research/**/*.log`. Research records of those types are then tracked like any other record in every lane's folder, instead of each lane discovering the silent drop (pin: 1,255 of 3,528 files; futures OI needed a force-add for C1).
- **Not chosen:** a negation file per research folder. It works, and it fails silently in every folder that forgets it.
- **What the block does not do:** it does not re-admit a folder that is ignored as a directory (a `data/` rule still wins), and it does not stop a raw dump over 40 KB from being added. PK Protocol P1 keeps those out of git; lanes commit by explicit path (P4 step 3) and list files over 40 KB before adding.
- The scoped file under `docs/research/pin_proof/` becomes redundant. It is the pin lane's file and is left as it is.
- Check (in `apply_i002.py`, can fail): after the edit `git check-ignore` must report a probe path `docs/research/_probe/x.txt` as NOT ignored and `logs/_probe.log` as ignored.
