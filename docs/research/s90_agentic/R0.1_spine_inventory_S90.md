| Write path | `merdian_calibrate.py` CLI (absent) | **`update_parameter()` RPC, `SECURITY DEFINER`, `GRANT EXECUTE … TO anon`** (`:160-233`) — closes the old row and inserts the new one |
| Read policy | — | `merdian_parameters_anon_read … TO anon` only (`:309`) |
| Seeds | — | 11 rows in the same file (`:241-300`) |

**Finding R01-F2 — the S89 pin-state seed cannot reach its reader. CONFIRMED (P1).** Live `chk_value_type_valid` = `value_type = ANY ('numeric','text','boolean','jsonb')`. The seed runs in one `BEGIN … COMMIT`; `ON CONFLICT DO NOTHING` does not absorb a CHECK violation, so **the whole seed aborts on its first row** and nothing lands. `sql/2026-10-03_s89_seed_pin_state_params.sql` writes `value_type = 'num'`; the CHECK allows `'numeric'`, and `get_parameter_num()` filters `value_type = 'numeric'`. Either the transaction aborts or the rows are invisible to `core/pin_state.py:117-121`. **Fix is one token ×8 (`'num'` → `'numeric'`), before the apply.**

**Finding R01-F3 — "0 rows" is the reader. CONFIRMED (P1):** `n_live_tup = 16`, `reltuples ≈ 13`, RLS on, one policy `merdian_parameters_anon_read TO anon`, and `merdian_ro` counts **0**. TD-S89-NEW-2 measured 0 rows through `merdian_ro`. The only policy is `TO anon`, and TD-S81-NEW-16 names `merdian_parameters` among the tables `merdian_ro` reads as silently empty. TD-S79-NEW-2 records `wall.band.*` and `wall.iv_floor_min` driving live views at S79. The table holds **16 rows**; the repo seeds account for 14 keys (11 bootstrap + `wall.band.NIFTY/SENSEX` + `wall.iv_floor_min`), read in full as `postgres` (SQL editor, one execution, 2026-10-05 08:48 IST): **all 16 rows are accounted for** — 11 S39 bootstrap seeds (2026-05-27), 2 S40 write-path verification rows on `pin.tau.NIFTY` (0.30 → 0.25 → restored 0.30 within 30 s, `S40 P1 verification`), and 3 S79 rows (`wall.band.NIFTY/SENSEX` 1.5, `wall.iv_floor_min` 120, 2026-09-15). **No change since 2026-09-15 and none unexplained**, so the open write path (R01-F4) shows no use beyond the operator's own.

**Finding R01-F4 — a public write path exists, and it is the intended one. CONFIRMED (P1 + Marketview source).** `update_parameter` is `SECURITY DEFINER`; its ACL is `{=X/postgres, …, anon=X/postgres, …}` — **EXECUTE for PUBLIC and for anon**. Marketview's Settings page calls it from the browser as anon (`meridian-connect` `src/lib/queries.ts:603-621`, `src/pages/Settings.tsx:51`). So **ENH-83 did ship a write path** (an RPC plus a UI, not the CLI ADR-016 names), and TD-S89-NEW-2 is wrong on both counts — the table is not empty and the write path exists. **The exposure:** the page is behind oauth2-proxy but the RPC is not; anyone holding the public anon key can call it directly, and TD-S89-NEW-5 records that key reaching scanners. Marketview does not pass `p_changed_by`, so every change, legitimate or not, records `changed_by = 'operator'`. **Display-only today** (S37: nothing routes on these).
