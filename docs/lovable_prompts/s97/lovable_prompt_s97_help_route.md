## 1. Data: one static fetch

On mount, fetch `${import.meta.env.BASE_URL}help/manual.json`. `BASE_URL` is `/` live and `/staging/` on staging, so never hard-code a leading `/`.

Shape:

```ts
type Shot = { file: string; caption: string; symbol: string; date: string; time_ist: string; board_bundle: string };
type Section = { id: string; title: string; html: string; shots: Shot[] };
type Part = { id: string; title: string; intro_html: string; shots: Shot[]; sections: Section[] };
type Manual = { title: string; manual_version: string; board_bundle: string; source_sha256: string;
                preface_html: string; parts: Part[] };
```

Each `shot.file` is relative (e.g. `help/shots/nifty_0952_pin.jpg`). Load it from `${import.meta.env.BASE_URL}${shot.file}`.

## 2. Rendering rules (fixed)

- Render every `*_html` field with `dangerouslySetInnerHTML`, in document order: `preface_html`, then for each part its `title` (as a heading) and `intro_html`, then each section's `title` (sub-heading) and `html`.
  - The HTML is generated by us from our own Markdown and contains only `p, ul, ol, li, strong, em, code, table, thead, tbody, tr, th, td, blockquote`. Do not rewrite, summarise, reorder, truncate or "improve" any of it.
- Style that HTML so it reads well in the board's existing dark theme. Use the same tokens, fonts and tabular numerals as the Board. Tables, inline `code` and nested lists must be legible on desktop and phone. No horizontal page scroll; wide tables may scroll inside their own box.
- **Anchors.** Give each part and each section the DOM `id` from the JSON (`part.id`, `section.id`). `/help#s3-5` must open scrolled to §3.5.
- **Contents.** A table of contents built from part and section titles, linking to those anchors. On desktop it is a sticky left column; on phone it is collapsible. Its words are the JSON titles, nothing else.
- **Screenshots.** Show each `shots` entry as a figure directly after the HTML of its part or section:
  - the image at full column width, not cropped and not recoloured;
  - under it, `caption`;
  - then the stamp line in §4.3.

  Clicking an image opens it full-size in an overlay. Build the overlay yourself; no package. Escape or a click outside closes it. Images use `loading="lazy"`.
- **Header line** under the page title: the §4.2 string.
- **Behaviour.** No keyboard shortcuts on this page. In particular, do not bind `?`, which the Board already uses for its key list. The Board's own shortcuts must keep working on the Board.
- **Never show a number or word that is not in the JSON**, except the five strings in §4.
