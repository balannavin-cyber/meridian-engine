- ✅ **Mixed-EOL files exist and normalising them is a silent rewrite.** A predominant-EOL detect-and-restore — correct for single-convention files — would rewrite line endings invisibly. **For document edits, do no normalisation at all: match each insert to its local region.** *(The example that produced this rule — `CURRENT.md` at 317 CRLF / 2,596 LF — no longer holds: measured **0 CRLF / 3,038 bare LF** at S75 2026-09-09. The rule is unaffected; the illustration is historical. §D.34.3.)*
- ✅ **Time-range fetchers must bind BOTH ends.** A `gte`-only PostgREST filter is an open-ended forward window: harmless on a `today` run (the newest row IS today's) and silently catastrophic on any `--as-of` backfill, where it stamps *today's* values onto every historical row. Bind `lte` / an `UNTIL_ISO` as-of ceiling. The tell in the data is a column that *varies* while its neighbours are frozen — that column is the one whose fetcher bounds both ends. (S68, `177aa3a`)
- ✅ **Store the raw anchor, not the derived scalar.** `front_expiry` (a date) beats a computed `dte` (an int): the view derives DTE *and* cycle-progress *and* rollover boundaries from the stored series, and the value was already in hand. Emit what you have; let the read layer derive. (ENH-116 Objective 1, S68, `ddd7077`)

- ✅ **Expiry-day 0-DTE flat-vol net_gex is numerically UNRECONSTRUCTIBLE intraday → live-sourced, not reconstructed** (Session 62, 2026-07-01) — As T→0 the ATM gamma blows up and net_gex becomes a near-singular sum of explosive nearly-cancelling terms; a flat-vol reconstruction is stable in the morning (ratio ~0.97) but detonates into sign-flipping chaos in the afternoon (−7×/+181M) — `diag_1125.py` on 2025-11-25. Rule: expiry days are classified **live-sourced** (union live `gamma_metrics` tagged `source='live_gamma_expiry'`; backfill emits an explicit logged `SKIPPED_EXPIRY`), never papered over with a T-floor. This is the same discipline as ADR-001 stable-lies — do not loosen the reconstruction to force a number where the math is singular. (Note: the pre-existing `hist_gamma_metrics` handled expiry days cleanly because it used real vendor Greeks, not flat-vol — it does not have this disease.)

- ✅ **Dhan EOD historical publish-lag is expected, not a stall — `compute_date_window()` (T−1, 220-day) is correct; don't patch the window to force a missing latest day in (Session 65, 2026-07-07).** 07-03/07-06 absent from `equity_eod` after a sweep was **Dhan-side EOD availability lag**, not an ingest bug: `compute_date_window()` uses a fixed T−1 lookback (`to = today−1`, `from = to−220`) with no lower-bound pin and no cursor-date exclusion, so on 07-07 the window (2025-11-…→2026-07-06) already *includes* the “missing” days — they simply hadn't published yet. Dhan's daily historical endpoint routinely lags 1–3 days on settled EOD (the `EOD_SAFE_LAG_DAYS` machinery exists precisely for this) and the hole self-heals on the next EOD run. Rule: a missing latest-day-or-two is provider publish-lag, not a defect — do not loosen the window or the denominator to paper over it (same discipline family as ADR-001 stable-lies).
- **Dhan EOD candle publish lag (1–3 trading days) means the day's frontier fills gradually — a "stuck at T-1" frontier is expected, not a bug, and self-heals on the next full sweep (S67, re-confirms S65).** 07-07 climbed 28%→94% across one session's laps + an unattended writer; the builder's 95% gate correctly held DMAs at the last complete date until 07-07 crossed the threshold. Don't patch the window or force a partial day; let the gate hold. (TD-S66-NEW-5 was not a bug — folded into the ingest-layer carry.)
- ✅ **A view CTE referenced once is INLINED (PostgreSQL ≥ 12), and a ranking or window CTE joined against mis-estimated CTEs can then run once per output row.** Measured S83 on the L10 surface: **2,715 ms**, with the k98 ranking CTE at `loops=876` and the header CTE re-scanned **767,376** times, from row estimates of 1 against actuals of 876 and 4. Marking `px`, `hdr`, `k98r` and `legmeta` **`AS MATERIALIZED`** took it to **28.1 ms** — a 96.6× reduction — with `k98r` at `loops=1`. **Two obligations, not one:** verify `loops=1` in `EXPLAIN (ANALYZE)` rather than assuming the hint took, and **prove the change inert by byte-identical before/after outputs** — the hint changes the plan, so nothing but a diff of results establishes that it changed nothing else. The gate stays where it was set; the body changes.

- **Historical backfills must NOT trust the DB `trading_calendar` gate — use a local weekday filter + API 404 as holiday ground truth (S63, Rule 18 corollary).** The gate fail-opens on historical dates the (days-220-reseeded) table doesn't cover, inflating a 270-day plan to 382 and running ~400 slow sequential lookups. For any historical backfill, filter Mon–Fri locally and treat the NSE-archive 404 as the holiday signal (MISS ≠ FAIL). Also: PostgREST query params use **list-of-tuples**, never a dict — Python silently drops a duplicate key.

Seed re-label is a DEAD END; the view is scoped `source = 'expiry_memory_live'` so the four-lens note never blends with gamma-only seed rows. Base rates fill by forward accrual only.
